## Claude Partner Network
MasterFabric is a Claude Partner Network partner. In the AI transformation flow, the studio plans, builds, and reviews custom software with Claude in the loop. Claude is part of the delivery practice. It is not a product MasterFabric resells, and membership is not a claim that every project uses Claude.

On the site: https://masterfabric.co/#claude-partner-title
Meeting request: https://masterfabric.co/contact/ or info@masterfabric.co. The site also offers a meeting request after someone has been on a page for a few seconds. That form is the same project-inquiry form, not a separate program application.

How an engagement runs when Claude is in the loop:
1. Take the brief — process, data, and what done means for an institution or a private client
2. Plan with Claude — architecture, flows, and the agent plan before the production system is written
3. Build in review — agents draft; engineers stay in the loop for design, security, and decisions Claude should not make alone
4. Prove and hand over — tests, fixes, and deploy in the same pass; the client owns the software

AI-native SDLC with Claude Code:
The same lifecycle runs in the terminal with Claude Code. An engineer states the task. Claude Code reads the repository, drafts the change, and runs the checks. The review stays with the engineer: plan in the repo, draft the diff, prove it in that session, then accept it before it ships. Claude Code is the agent in the pass. It is not a product MasterFabric resells.

What that looks like in the work:
- Institutions: the system follows the process they already run, including the AI transformation they asked for
- Private clients: bespoke software, not a package they have to bend; Claude for the thinking and the draft, MasterFabric for what has to live in production
- The studio: the AI SDLC taught in MasterFabric Academy is the same one used in delivery; the plan, the review, and the deploy stay visible

## AI Portfolio
AI Portfolio — https://masterfabric.co/ai-portfolio/

Figures below are quoted from the site's snapshot of each repository's main branch (commit SHA and date given); do not round, extrapolate, or present them as production results.

### Lakehouse Lab
- Page: https://masterfabric.co/ai-portfolio/lakehouse-lab/
- GitHub: https://github.com/masterfabric/masterfabric-lakehouse-lab
- Snapshot: 6ba927f (2026-11-23)
- What it is: A complete lakehouse you can run on one laptop, fed by a synthetic mobile operator.
- Measured: Scale benchmark ran from 0.26 M to 2.1 M raw rows (scales 1 to 8); total pipeline time grew from 32.43 s to 68.59 s, so 8x the data costs 2.1x the time.
- Measured: Throughput through bronze to gold rises from about 11k to 62k rows/s as scale increases.

### Realtime Telco
- Page: https://masterfabric.co/ai-portfolio/realtime-telco/
- GitHub: https://github.com/masterfabric/masterfabric-realtime-telco
- Snapshot: 456e642 (2026-11-23)
- What it is: Streaming network monitoring for a mobile operator, small enough to run on one laptop.
- Measured: Live run: 240 cells over 6 simulated hours at 30x delivered 520,931 events in 12 minutes.
- Measured: Detection on the held-out seed: 36/36 incidents found, 45 alerts, 2 false, precision 0.956, recall 1.0, type accuracy 1.0.

### Airflow MLOps
- Page: https://masterfabric.co/ai-portfolio/airflow-mlops/
- GitHub: https://github.com/masterfabric/masterfabric-airflow-mlops
- Snapshot: 3546e6f (2026-11-23)
- What it is: Replays a year of telco churn modeling on Airflow, MLflow, Evidently and Feast with measured retraining results.
- Measured: Backfill: 12 monthly runs (2025-12 to 2026-11), all successful, 60,000 to 66,274 subscribers, 1.2-8.4 s of task time per month.
- Measured: Realised AUC, 2026-10: auto policy (v4) 0.830 vs never retrained (v1) 0.789, oracle upper bound 0.841.

### On-Prem LLM Stack
- Page: https://masterfabric.co/ai-portfolio/onprem-llm-stack/
- GitHub: https://github.com/masterfabric/masterfabric-onprem-llm-stack
- Snapshot: bd383f7 (2026-11-23)
- What it is: An on-prem LLM platform in one Helm chart on local Kubernetes, with RAG, guardrails and monitoring.
- Measured: Corpus of 23 documents ingested into 207 chunks, with ingest taking 57-58 s (embedding on 1 CPU thread).
- Measured: Retrieval hit@4 0.933 on 30 questions with a known source, median 0.6 ms in pgvector (HNSW), 46 ms to embed the question.

### LLM Serving Bench
- Page: https://masterfabric.co/ai-portfolio/llm-serving-bench/
- GitHub: https://github.com/masterfabric/masterfabric-llm-serving-bench
- Snapshot: 83af7fe (2026-11-23)
- What it is: Measured LLM serving benchmarks comparing llama.cpp and MLX on Apple Silicon across quantization, concurrency, context and speculative decoding.
- Measured: Peak output throughput, Q4_K_M, 4 concurrent requests: 381 tok/s on the Metal GPU vs 184 tok/s in the CPU container.
- Measured: Peak output throughput, Q8_0, 4 concurrent: 358 tok/s Metal vs 328 tok/s CPU container (reproduced in a second run at 335 vs 181).

### Secure Data AI
- Page: https://masterfabric.co/ai-portfolio/secure-data-ai/
- GitHub: https://github.com/masterfabric/masterfabric-secure-data-ai
- Snapshot: 8ef6054 (2026-11-23)
- What it is: Data security controls for AI, measured on synthetic Turkish data: PII masking, column policies, secure RAG and OWASP LLM guardrails.
- Measured: PII detection on 2,000 labelled notes with decoys: precision 0.986, recall 1.0 (pattern-only precision: 0.680).
- Measured: Column/row policies, 200,000 customers, 5 roles: 0 of 50 bypass attempts allowed, all 60 attempts audited.

### GenAI Foundations
- Page: https://masterfabric.co/ai-portfolio/genai-foundations/
- GitHub: https://github.com/masterfabric/masterfabric-genai-foundations
- Snapshot: 9e3b863 (2026-11-23)
- What it is: From-scratch PyTorch implementations of transformer, LoRA, GAN, WGAN-GP, diffusion, classifier-free guidance and DPO with measured results.
- Measured: Attention implementation matches torch.nn.functional.scaled_dot_product_attention within 1.5e-7.
- Measured: The 0.82M-parameter character-level GPT reaches a validation loss of 1.516 nats/char (uniform guess 4.72), in 48 s on MPS at 257,929 tokens/s.

### Spark Rust Bench
- Page: https://masterfabric.co/ai-portfolio/spark-rust-bench/
- GitHub: https://github.com/masterfabric/masterfabric-spark-rust-bench
- Snapshot: 361bb4a (2026-11-23)
- What it is: Benchmarks five SQL engines on identical queries over 10M to 200M synthetic telco records, including Iceberg table reads.
- Measured: Polars ran the same SQL 3.7x faster than PySpark at 200M rows (5.9x at 10M) using less than half the memory; at 200M rows the sum of six query medians was 4.325 s for Polars, 4.777 s for DuckDB, 5.532 s for DataFusion and 15.975 s for PySpark.
- Measured: PySpark SQL is as fast as Scala SQL: 15.975 s vs 15.922 s for the sum of six query medians at 200M rows.
